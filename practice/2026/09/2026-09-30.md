### Merge Intervals
- Identified the need to sort intervals by start value first.
- Sorting is O(n log n); the merge pass is O(n), so overall time is O(n log n).
- Worst-case result space is O(n).
- Implemented the solution cold in C#.
- Used `Math.Max(currentEnd, nextEnd)` when merging contained/overlapping intervals.
- Discussed caller mutation and reference semantics with `int[][]`.
- Identified two mutation points:
  - `Array.Sort(intervals, ...)` reorders the caller's outer array.
  - Updating an inner `int[]` mutates the same referenced array.
- A shallow outer copy is insufficient if inner arrays will be mutated; copy the inner arrays as well when mutation must be isolated.

## .NET — Async/Await

### Mental model corrected

Before:

> await puts I/O outside the main thread.

After:

> await suspends the async method without blocking the executing thread. While asynchronous I/O is pending, the thread can return to the thread pool. When the operation completes, the continuation is scheduled.

### Concepts practiced
- `Task` is not a thread; it represents an asynchronous operation and its completion/result/failure/cancellation.
- Thread-pool threads are execution resources that run code.
- I/O-bound vs CPU-bound work.
- `await` vs blocking with `.Result` / `.Wait()`.
- `Task.Run` moves CPU work to a thread-pool thread; it does not remove the CPU/thread cost on an ASP.NET server.
- Pending network I/O does not require a .NET thread to sit and watch the socket.
- Sequential awaits vs starting independent async operations before awaiting them.
- `Task.WhenAll` for explicitly awaiting independent concurrent operations.
- Concurrency should be bounded when downstream/resource limits matter.

### Key sentence

**`await` suspends the method, not the thread.**

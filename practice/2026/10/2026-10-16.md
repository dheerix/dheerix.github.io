## AI Engineering

### RAG pipeline
Offline: sources -> chunks -> embeddings -> vector/index store + metadata.

Online: question -> hybrid retrieval -> candidate topK -> rerank -> small context -> LLM -> answer.

Retrieval returns evidence/context; the LLM generates the answer.

### Retrieval and reranking
- Vector search handles semantic similarity.
- Lexical/BM25 helps exact IDs, exception names and terminology.
- Metadata handles structured constraints such as date, version and source.
- Broader candidate K favors recall.
- Reranking narrows the candidate set for higher precision/context quality.
- Higher K is not automatically better because latency, cost and noise increase.

### Chunking and freshness
- Blind fixed-size chunks can split semantic units.
- Prefer structure-aware chunking where possible.
- Carry source/version/status metadata.
- Update or remove stale chunks when source documents change.
- Conflicting current/obsolete evidence should not be resolved by confident guessing.

### RAG vs tools
- Organizational/static-ish knowledge -> RAG.
- Current authoritative state -> runtime API/tool.
- Actions/changes -> tool/API.
- Mixed questions can combine tool results and RAG evidence.

### Tool calling and MCP
Tool loop: model requests tool + arguments -> application validates/authorizes -> application executes -> result returns to model.

The model does not directly execute backend operations.

MCP is a standardized integration boundary for AI hosts to discover/access tools/resources/context. It does not replace underlying APIs.

Tool calling = model chooses a tool.
MCP = standardized way the AI application exposes/connects those capabilities.

### Evaluation
Failure classes:
1. Retrieval failure: evidence exists but was not surfaced.
2. Reranking failure: retrieval found it but reranker dropped it.
3. Generation failure: sufficient evidence reached the LLM but the answer was wrong.

Concepts:
- Recall@K: did relevant evidence appear in top K?
- Precision@K: how much retrieved material is relevant?
- Groundedness/faithfulness: are claims supported by evidence?
- Answer relevance: did the response answer the question?

Use a golden eval dataset for offline evaluation, then controlled rollout and production signals. Feed real production failures back into the eval set.

### Bedrock and LangChain
Bedrock mental model: AWS-managed generative-AI platform providing access to supported foundation models and surrounding managed capabilities.

LangChain is optional. Direct SDK/model integration is valid. LangChain becomes useful when reusable orchestration abstractions help with retrieval, prompts, tools, structured output and workflow composition.

### Security
Authorization belongs at the retrieval/tool boundary, not in an LLM prompt. Filter knowledge by the authenticated user's permissions before chunks enter model context. Backend authorization still applies to every requested tool action.

Principle: the LLM is never the security boundary.

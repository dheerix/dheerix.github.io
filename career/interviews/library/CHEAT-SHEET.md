# Senior / SDE3 Interview Cheat Sheet

> Five-minute pre-interview revision. Prompts, not scripts. Never invent metrics or personal ownership.

## Positioning (30 seconds)
**14+ years | Full-stack + cloud + production AI | Modernization | End-to-end ownership**

“I build and evolve production systems across backend, frontend, cloud, and AI workflows. My strength is connecting business needs to engineering decisions and following those decisions through delivery and operations. I’m looking to deepen that hands-on ownership and technical leadership.”

## Universal answer: C-D-T-A-O-L
**Context → My Decision → Trade-off → Action → Outcome → Learning.**
Keep the first answer concise. Expand only when asked. Separate **I** from **we**.

## Eight story anchors

| Prompt | Story | What to emphasize |
| --- | --- | --- |
| Ownership | Dealer Operating System transition | Domain boundaries and production readiness |
| Led without title | Guardlane coordination | Reduced uncertainty and aligned stakeholders |
| Architecture | Oracle/Java → cloud modernization | Incremental migration versus rewrite |
| AI engineering | Guardlane | Rules + classifier + fallback, evaluation, HITL |
| Business impact | AI Upload / enterprise search | Product workflow and verified outcome |
| Mistake / feedback | Large PR | Review boundaries, self-review, changed habits |
| Ambiguity | Similar Listings | Confirm exact edge case before telling |
| Mentoring | System-map onboarding | Confirm one engineer's observable outcome |

**Each story needs:** 1 personal decision, 1 alternative, 1 result, 1 learning. Mark unverified facts explicitly.

## Generic answers
- **Why change jobs?** Broader technical ownership, architecture influence, stronger growth opportunity. No negativity.
- **Why Senior / Tech Lead?** Influence through design clarity, production judgment, and team leverage—not title.
- **Why this role?** Specific company problem + relevant example + intended contribution.
- **Strength?** Work across system boundaries without losing production detail.
- **Weakness?** A genuine bounded gap, repair routine, and progress evidence.
- **First 90 days?** Map critical flows and ownership → ship a safe improvement → own a meaningful initiative.
- **Tell me about yourself?** Present scope → 2 career highlights → current strengths → role fit.

## Technical reasoning
- **System design:** Business goal → functional/nonfunctional requirements → scale → invariants → APIs/data → components → failure modes → security/observability → trade-offs.
- **Coding:** Clarify → sample → brute force → invariant/pattern → code → tests → complexity.
- **Production incident:** Impact → timeline → evidence → hypotheses → isolate → mitigate → verify → prevention.
- **AI/RAG:** Data quality → retrieval/evaluation → grounding → fallback → permissions → cost/latency → monitoring.
- **Disagreement:** Competing incentives → options → evidence → decision → commitment.
- **Unknown answer:** “Here’s what I know, what I’d verify, and how I’d test it.”

## Ask the interviewer
1. What consequential decisions would I own in the first six months?
2. Where does delivery lose predictability today?
3. What distinguishes strong Senior from Tech Lead performance?
4. How do you balance modernization with delivery?

## Last 30 seconds
**Slow down. Answer first. Think aloud. State trade-offs. Be precise, not impressive.**
**No invented numbers. No unexplained tech lists. No team achievements claimed as solo work.**
